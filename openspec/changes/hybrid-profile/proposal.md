# Proposal

> Draft from an explore session on 2026-10-26. The direction and the main decisions are agreed; `design.md` lists what is still open.

## Why

The profile is meant to be a summary Friday always has at hand, but it is built as a page of its own: facts about the user are written to it and live nowhere else. In practice the profile holds the user's hobbies, motorcycles, car, cats and routine with no page behind any of them, and doesn't even link the pages that do exist (`Home`, the Honda project). The consolidation guidance only gives pages to people, places, projects and organisations, exempts entities known by name and relation alone, and linking is a prompt instruction that nothing checks. The user also wants a place to steer Friday: personal settings and tweaks that act as an extension of the system prompt, which Friday has no hook for today.

## What Changes

- **The profile becomes hybrid.** It holds two parts:
  - **Instructions**: written by the user in the portal only, never by a tool or the nightly pass, added to every voice and chat prompt as directives to follow. One block for both channels, with its own size limit.
  - **Summary**: generated by the nightly pass from the pages, within the profile budget, every line backed by and linked to the pages it summarizes. Read-only in the portal.
- **A page about the user.** Facts about the user get their own person page (the profile's *subject*), referenced by id. `brain_remember` with entity `profile` (or `me`) and extraction's "facts about the speaker" write there. Facts about the household as a whole go to a household page. **BREAKING** for the profile's role: nothing appends to the profile any more.
- **Nothing lives only on the profile.** Every fact the summary states is on a page. The rule that let name-and-relation-only entities stay on the profile goes away.
- **Hobbies, belongings and pets are entities.** The guidance gives them pages: a hub page per hobby or topic, and a page of its own for an item once it holds facts of its own.
- **Links are made by code.** Writes by `remember`, `extraction` and `consolidation` link the first mention of a live page's name or alias. The user's own edits are left as typed.
- **Pages name the user.** Guidance writes relations as "Raymond's sister", not "the user's sister", so pages stay unambiguous if Friday ever serves more than one person.
- **Migration.** The current profile body moves to a new subject page (seeded as `Me`, renamed by the user in the portal). The current body stays as the summary until the first generation. The guidance version is bumped so the next nightly run splits the subject page into entity pages and generates the summary.
- **Portal.** The profile view shows the editable instructions and the read-only summary with its links. The subject page is marked as the user's page and cannot be deleted.

Out of scope:
- Several users, identity, and private pages. The intended direction is recorded in `design.md`.
- Separate instructions per channel.
- Writing instructions by voice or chat. "From now on…" becomes a fact on the user's page.
- Regenerating the summary immediately after every write. The nightly job can be started by hand.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `brain`: the profile's structure (instructions and summary, a subject page), what `brain_remember` writes for `profile`, what the prompt context contains and how it frames instructions, the profile budget, the pages API and the portal's profile view, and automatic linking on non-user writes.
- `brain-maintenance`: extraction routes facts about the speaker to the subject page; consolidation no longer rewrites the profile but generates its summary in a validated step; the guidance covers hobbies, belongings and pets and names the user; the profile-specific preservation rules are replaced by a backing check on the summary; new fixtures.

## Impact

- `modules/brain/src/schema.ts`: a migration adding the instructions, the subject reference and the summary's bookkeeping, and moving the current profile body to the subject page.
- `modules/brain/src/store.ts`, `tools.ts`, `context.ts`, `routes.ts`, `links.ts`: subject resolution, instructions, prompt framing, the API, auto-linking.
- `modules/brain/src/nightly/` (`guidance.ts`, `extract.ts`, `consolidate.ts`, `render.ts`, `job.ts`, `runs.ts`): routing, the summary step, the guidance, `GUIDANCE_VERSION`.
- `modules/brain/src/ui/` (`BrainPage.vue`, `PageView.vue`): the profile view and the subject page.
- `modules/brain/test/` and `test/fixtures/nightly`: tests and fixtures, including the eval.
- Docs: README and the brain section of `openspec/config.yaml` context. No new configuration keys are expected; `BRAIN_PROFILE_TOKEN_BUDGET` becomes the summary's target.
- In flight: `oauth-connections` and `sonos-speakers` don't touch the brain module. `document-store` (planning) doesn't either. A brain module migration is numbered within the module, so it doesn't compete with core migrations.
